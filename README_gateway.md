# بوابة الاستضافة الخارجية (Gateway)

## لماذا؟
صفحات Apps Script تُعرض داخل إطار تستضيفه Google، وسلوكها يعتمد على **الحسابات المسجَّلة في متصفحك** (اختيار الحساب `/u/1/` والكوكيز والإضافات). هذا خارج سيطرة كود المنصة، ولذلك قد تظهر «تعذر فتح الملف» أو شاشة بيضاء عند تعدد الحسابات رغم أن الكود سليم.

**الحل البنيوي:** تُستضاف الواجهة كملفات عادية على موقعك (أو أي استضافة)، وتكلّم Apps Script كـ **API مجهول** عبر `fetch` **بلا كوكيز**، فلا يتدخل أي حساب Google في الجلسة. الخادم والقواعد والصلاحيات كما هي بلا تغيير؛ فقط تغيّر طريقة وصول الواجهة إليها.

## الملفات (ارفعها كلها)
| الملف | الوظيفة |
|---|---|
| `index.html` | المنصة (الدخول، الطالب، المدرب، الموظفون) |
| `site.html` | الموقع العام وصفحات الدورات والدبلومات والتحقق (يُفتح تلقائيًا من `?page=public|verify|course|diploma`) |
| `config.js` | **الملف الوحيد الذي تعدّله**: رابط خادم Apps Script، ورمز المؤسسة الافتراضية `SCI_ORG` |
| `manifest.webmanifest` `sw.js` `icon-*.png` | تثبيت المنصة كتطبيق على الجوال (PWA) — انظر `mobile/README_mobile_ar.md` |

## الخطوات

### 1) جهّز خادم Apps Script
1. حدّث ملفاتك بالنسخة الأخيرة (خاصة `SCI_Web.gs` ففيه `doPost` الجديد)، ثم `SCI_runDiagnostics` (يجب أن تظهر «تقديم صفحات الويب» ✓).
2. `Deploy ← Manage deployments ← Edit ← New version ← Deploy`، وتأكد أن **Who has access = Anyone**.
3. انسخ **Web app URL** (ينتهي بـ `/exec`).
4. اختبر: افتح `رابطك/exec?api=ping` في المتصفح. يجب أن يظهر JSON فيه `"ok":true`.

### 2) اضبط `config.js`
افتحه وضع رابطك مكان النص الافتراضي (أبقِ علامتي الاقتباس):
```js
window.SCI_API_URL = 'https://script.google.com/macros/s/AKfycb.../exec';
```

### 3) ارفع كل الملفات إلى استضافة
**GitHub Pages (مجاني، يعمل من الجوال بوضع «نسخة الكمبيوتر»):**
1. أنشئ حسابًا ثم مستودعًا جديدًا (Public) مثل `sci`.
2. `Add file ← Upload files` وارفع **كل ملفات المجلد** (بعد تعديل `config.js`) ثم Commit.
3. `Settings ← Pages ← Deploy from a branch ← main / (root)` ثم Save.
4. بعد دقيقة يعمل الرابط: `https://اسمك.github.io/sci/`.

**بدائل:** Cloudflare Pages (Direct Upload) أو Netlify أو أي استضافة ويب عادية: ارفع الملفات الثلاثة في مجلد واحد.

### 4) اضبط روابط البريد والشهادات
في المنصة: **الإعدادات ← رابط التطبيق المعتمد** = رابط الاستضافة (مثل `https://اسمك.github.io/sci/`). عندها يشير رابط استعادة كلمة المرور ورابط التحقق المطبوع على الشهادات إلى البوابة لا إلى رابط Google.

### 5) Blogger
ضع في قائمة المدونة رابط البوابة، أو للموقع العام صفحة HTML فيها:
`<iframe src="https://اسمك.github.io/sci/site.html" style="width:100%;height:1400px;border:0"></iframe>`

### 6) الاختبار
افتح رابط البوابة في **Chrome العادي** وأنت مسجَّل بأكثر من حساب Google، وسجّل الدخول. وشارك المستخدمين **رابط البوابة فقط** لا رابط `/exec`.

## ملاحظات مهمة
- **الأمان:** رابط `/exec` يمكن لأي أحد استدعاؤه (كما كان)، وكل الحماية في الخادم: جلسات، قفل بعد 5 محاولات، تحديد معدل الدخول (120/دقيقة)، وصلاحيات لكل عملية. لا تعامل الرابط كسر، ولا تضع في `config.js` غيره. رمز الجلسة يُرسل في جسم الطلب لا في الرابط.
- **سرعة:** أول طلب بعد خمول قد يستغرق 1–3 ثوانٍ (طبيعة Apps Script).
- **الجلسة** تُحفظ في `sessionStorage` لموقعك: بإغلاق التبويب يُطلب الدخول مجددًا.
- **التحديثات:** عند تحديث ملفات الواجهة تُعاد إليك نسخ جديدة من `index.html` و`site.html`؛ استبدلهما واترك `config.js`. (للمطورين: `node tools/build_gateway.js`).
- **الاستضافة المزدوجة:** رابط `/exec` القديم يبقى يعمل لمن يستطيع فتحه؛ لا تعارض.
- **ما لم أستطع اختباره:** تشغيل هذه البوابة على Google فعليًا (CORS وإعادة التوجيه). الاختبارات المحلية تحاكي الخادم. إن ظهر خطأ «استجابة غير متوقعة» فتحقق من: الرابط ينتهي بـ `/exec`، والوصول Anyone، ونتيجة `?api=ping`. وإن ظهر خطأ CORS في Console فأرسل لي نصه.
- **مانعات الإعلانات:** قد تحجب بعضها طلبات `script.google.com`؛ إن حدث، أضف موقعك للقائمة البيضاء.

## تعدد المؤسسات
- كل مؤسسة لها رابط: `https://موقعك/?org=alnoor` (يمكن ضبط `window.SCI_ORG = 'alnoor'` في `config.js` لتكون هذه النسخة مؤسسة افتراضية، ولكل مؤسسة نسختها من البوابة إن أردت رابطًا مستقلًا).
- الجلسات والبيانات مفصولة بالمؤسسة؛ لا يلزم تعديل الخادم.
